# 开发者指南

面向改动代码的人：架构在哪、契约是什么、怎么验证、怎么发布。
使用与配置见 [使用指南](使用指南.md)。内部设计推演见 `docs/视听融合架构设计.md` 与 `docs/dsh-pf-stream 技术设计方案.md`；这两份仅存本地、不随仓库或 npm 包发布，文中的版本结论按当时状态阅读。

## 架构地图

```text
src/index.ts          插件入口：Config、apply、inject（tools / subprocess / attachments）；webServer / credentials / configEditor / storageDomain 为可选服务
src/tool/schema.ts    工具定义（标准 JSON Schema，宿主不做归一化）
src/tool/handler.ts   一次调用的编排：probe → 路由到流式或确定性检视 → 挂台词 → 回 ContentBlock[]
src/entry/            参数归一化：顶层便捷字段 → intent；legacy 兼容
src/stage0/           ffmpeg/ffprobe：探测、解码、时间轴
src/stage1/           感知：梯度能量、清晰度波峰
src/stage2/           状态机：运动/静止切换检测
src/stage3/           采样：动态流式采样、确定性检视路由
src/stage4/           画布：打包、视窗裁剪、视觉角标
src/stage5/           控制器：密度档位与自适应调节、意图推导
src/stage6/           历史与预检：两级引用、KV-cache 稳定、体积预检
src/audio/            听觉边车：字幕 → VAD → ASR、幻觉清洗、缓存、挂载
src/asr/              转写引擎：预设表、探测、安装器、决策、官方语音输入适配、自检
src/host/             Web 面：状态、安装、配置写入、密钥、测试转写
client.js             插件页面板与启用引导（React.createElement，无构建步骤）
```

数据流：`probe` 拿时长/分辨率/音轨 → `audio` 决定台词来源 → 采样或检视产出 packet → 画布打包成 PNG → 宿主附件服务 → 返回文本块 + 图像块。

## 宿主契约（改代码前必须知道）

这些不是风格偏好，是宿主硬约束，`pnpm verify:host` 会检查：

1. **工具参数是标准 JSON Schema 根对象**：`type` / `properties` / `required` / `additionalProperties`（以及 `items`、`enum`、`const`、`description`）。`verify:host` 的关键字白名单是保守子集（不含 `oneOf`），工具注册路径不做归一化；未在 `properties` 声明的顶层实参键会被宿主剥掉。
2. **`output.render` 返回 ContentBlock 数组**：`[{ type: 'text', text }, { type: 'image', attachment }]`，返回值必须可无损 JSON 化。
3. **会话标识**：`exec?.sessionId ?? exec?.agent?.session?.id ?? 'default'`。
4. **附件上限**：宿主单条消息最多 20 张图；`saveImages` 返回引用，不是字节。
5. **运行时依赖只有 `pngjs` 与 `zod`**：`verify:host` 会断言依赖恰为这两个包（`Object.keys(dependencies).length === 2`）。不能加原生模块，不能把宿主包写进 deps。
6. **插件条目要能被装载**：`cordis.patch.yml` 的首个非注释行必须是 `- insert:`，且含 `id` 与 `name`。

## 转写引擎的决策链

`resolveAsr(config, intentLanguage, env, facts)`（`src/asr/engine.ts`）是纯函数，顺序固定：

1. `facts === undefined` → 0.2.x 旧语义（只认 `provider` 与 `apiKey`）。
2. `engine === 'off'` → 不转写。
3. `provider` 是旧值（非 `none`）且 `engine` 不是 `cloud`/`local`/`host` → 走 legacy。这是 0.2.x 兼容路径；要让老用户复用官方模型，需把 `engine` 设为 `host`，或清空旧 `provider`。
4. `engine === 'cloud'` 或（`auto` 且云端就绪）→ 校验 `baseUrl` / `model` / 密钥，缺一给具体 reason。
5. `engine === 'host'`，或 `auto`/`local` 且官方 provider 就绪 → 用 `host_sensevoice`；未就绪时 `host` 直接返回 reason，`auto`/`local` 继续回退。
6. `engine === 'local'` 或 `auto` → 看探测结果：缺引擎 / 缺模型分别给 `local_missing_engine` / `local_missing_model`。
7. 都不满足 → `none`，附一句可行动 detail。

密钥优先级：环境变量 `DSH_ASR_API_KEY` > 凭据存储 > 配置里的 `audio.asr.apiKey`（后者只为兼容，不建议用）。

官方 provider 的探测在 `src/asr/hostSpeech.ts`：`probeHostSpeech(service, preferredProviderId, language)` 只读 `snapshot()`，选 `location='host-local'` 且 **带非空 id**、phase 为 `ready`/`standby` 的 provider；有语言时优先 ready 且语言精确匹配的 provider。没有 id 的 host provider 不选，避免 `resolve` 按 id 命中同名云端 provider。语言用 `resolveHostSpeechLanguage` 归一化到 provider 列表的精确值（`zh-CN` → `zh`，空白 → `null`），因为官方 `resolve` 使用严格 `includes` 校验。服务句柄由可选服务注入登记和清理，探测结果每次调用重算，不缓存；也不调用 `prepare()`。`client.js` 只读 `status().host`，不自己推断。

`status().active` 用同一套 `resolveAsr` 算「当前实际会用哪个引擎」，面板据此显示「转写可用 · 本地/云端/官方语音」——不要让页面自己猜。

缓存键是 `视频指纹-引擎指纹`：引擎指纹由 `provider|baseUrl|model|language`（host 引擎为 `provider|model|modelLabel|language`）加 `args` 决定，**不含密钥**。换引擎必然换缓存，避免把本地的结果当成云端结果复用；host 引擎用 `provider='host_sensevoice'`、`model=providerId`、`modelLabel=provider 展示名` 隔离，切换 INT8/FP32 不会复用旧转写。

新增云端服务商：在 `CLOUD_PRESETS` 加一条（`id` / `label` / `baseUrl` / `model` / `protocol` / `keyRef` / `keyUrl` / `editable`），面板会自动出现。
新增本地引擎：在 `LOCAL_ENGINES` 加一条（`binNames` 用于 PATH 探测），并在 `buildLocalArgs` 给它的命令行模板。

## 配置写入

面板改配置走 **`ctx.configEditor.edit(entry, fn)`**，不是 `settings.update`。

原因：`settings` 的表单只投影 **volatile** 字段；本插件的 40 余项配置是普通字段，`describe()` 根本不会把条目投影出来（实测拿到 `null` 命名空间，写入 409）。`configEditor` 是官方给「编辑完整配置」的通道，写入走正常 Loader 路径，也会保留用户没碰的字段（`mergeConfig` 做深合并，数组整体替换）。

密钥不写配置：走 `ctx.credentials.resolve/set/unset`，`credentialRef('DSH_ASR_KEY_OPENAI')` 等 POSIX 标识符是凭据名；直接环境变量 `DSH_ASR_API_KEY` 优先于凭据存储与配置里的 `audio.asr.apiKey`（兼容项）。每次操作重新 resolve，切换密钥不需要重启。

## 插件页（client 半）

`client.js` 是纯 JS，由宿主的 client module loader 在浏览器里加载：

```js
window.__ModuleLoader__.load({
  id: 'dsh-pf-stream',
  factory(require) {
    const React = require('react');
    return { inject: ['slots'], apply(ctx) { /* ctx.slots.register(...) */ } };
  },
});
```

注册两个槽：

- `plugins.bundle.config`（key `dsh-pf-stream`）：插件详情页的设置面板，`view === 'summary'` 时返回 `null`。
- `plugins.bundle.activation`（key 同上）：用户显式启用后的引导卡。

清单与静态资源：

- `package.json` 要有 `exports['./client']`、`exports['./icon']`、`exports['./locale/*.json']`，以及 `dsh.client = { platform: 'web', immediately: true, inject: ['slots'] }`；`files` 必须同步列出 `client.js`、`icon.svg`、`locale/zh.json`、`locale/en.json`（`check:package` 不做 glob）。
- 插件显示名与描述来自 `locale/zh.json` 与 `locale/en.json` 的 `meta.title` / `meta.description`（「视频理解」/「Video understanding」）；图标是 `icon.svg`，≤256 KiB。

HTTP 接口（`src/host/api.ts`，前缀 `/dsh-pf-stream/api`）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/status` | 状态、预设、引擎、安装进度、当前配置值 |
| POST | `/install` | 下载模型与引擎（`target: all / model / engine`） |
| POST | `/install/cancel` | 取消当前下载 |
| POST | `/config` | 改一个配置字段（白名单：mode/engine/preset/baseUrl/model/language/modelId/threads） |
| POST | `/key` | 写入或清空预设的密钥 |
| POST | `/test` | 用 1 秒测试音跑一次真实转写 |
| POST | `/cache/clear` | 清理转写缓存（保留模型） |
| POST | `/detect` | 重新探测本地引擎 |

所有 POST 要求 `content-type: application/json`；带 `Origin` 的请求做同源校验。

规则：

- 不要 `require` 任何 Harness Client 包（`@deepseek-ai/dsh-client-ui-primitives` 等）；自己写控件，只用 `--dsw-alias-*` 主题变量并带 hex 兜底。
- 不要用 iframe；iframe 拿不到主题与语言，且官方实践明确禁止。
- 面板通过 `fetch('/dsh-pf-stream/api/...')` 与 host 通信；host 用 `ctx.webServer.register({ kind: 'prefix', path })` 注册，自带同源校验与 JSON 校验。
- 槽注册包在 try/catch 里：一个槽抛错会让整块空白，宁可少渲染。

## 测试与门禁

```bash
pnpm build         # tsc；必须先 build，vitest 有跑 lib 的用例
pnpm test          # 单元 + 边界 + 端到端
pnpm verify:host   # 宿主契约 13 项
pnpm check:package # npm pack 内容与 files 白名单一致
```

测试导入源码用相对路径 `../../../src/...`（vitest 直接跑 TS）。改安装器时，除了单测，务必用真实网络跑一次 `LocalAsrInstaller.start('all')`——下载源、压缩包目录结构、DLL 落位都只有真跑才暴露（0.3.0 就是这么抓到两个 bug 的）。

## 发布

发布由维护者明确决定后启动；完整检查单与失败处置见 [发布规范](发布规范.md)。

1. 四个门禁全绿，并确认 README 与文档描述的行为与实际一致。
2. `npm version patch --message "release: %s"`（按升型可用 minor）生成版本提交与附注 tag。
3. `git push origin main vX.Y.Z`，等升版提交的常规 CI 绿。
4. 创建 GitHub Release，绑定已存在的 tag（不要填 target），触发 `publish.yml` 的 OIDC + provenance 发布。
5. 按发布规范核验 registry、provenance 与本机安装；升级后必须重启 DSH。

已知限制要如实写：模型完整性目前按大小校验，不是逐字节哈希；本地转写的首次调用可能先回画面（`graceMs`，默认 60 秒），台词在后台补。

## 升级后的热更新

宿主对已加载模块做进程内缓存：重装 bundle 不会替换已加载的 host 半代码，**必须重启 DSH 应用**；client 半刷新页面即可。验证面板时先重启，否则看到的是旧逻辑。
