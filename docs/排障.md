# 排障

按现象查。每条都给出「怎么确认」和「怎么修」，不猜。

## 找不到 ffmpeg

**现象**：调用返回 `PFSTREAM_SPAWN_FAILED`，或设置页 ffmpeg 卡片是红色。

**确认**：终端执行 `ffmpeg -version` 与 `ffprobe -version`，两条都要有输出。

**修**：

1. 安装：Windows `winget install Gyan.FFmpeg`；macOS `brew install ffmpeg`；Ubuntu/Debian `sudo apt install ffmpeg`。
2. 装完新开一个终端再验证（PATH 变更对已开进程不生效）。
3. 不想进 PATH，就在插件配置里写绝对路径：

   ```yaml
   ffmpegPath: C:/tools/ffmpeg/bin/ffmpeg.exe
   ffprobePath: C:/tools/ffmpeg/bin/ffprobe.exe
   ```

定位顺序：配置 → `DSH_FFMPEG_PATH` / `FFMPEG_PATH` → `DSH_FFMPEG_DIR` → `~/.dsh/tools/ffmpeg/bin`、`~/.dsh/bin` → `PATH`。

## 有声音，但没有台词

**现象**：画面正常，`audio.status` 是 `no_subtitle_asr_unconfigured`，提示行里有一句「未生成转写文本…」。

**含义**：这段视频没有字幕，插件也没有可用的转写引擎。这不是故障，是还没设置。

**修**：打开左侧栏「插件」→「视频理解」，三选一：

- 点「下载本地模型」（约 190 MB），下载后点「测试转写」；
- 或选云端（OpenAI / Groq / 自定义兼容端点），填 Key，保存后点「测试转写」；
- 已装官方语音输入插件并准备好模型时，把引擎设为 `auto`、`local` 或 `host`，直接复用其 SenseVoice 模型。`engine=host`，或 `auto`/`local` 实际选中官方语音时，按钮显示「检查官方语音就绪」，只检查 provider 状态；真实转写在处理视频时执行。

**注意**：本地转写是「先回画面、后台补台词」。第一次调用时 `graceMs`（默认 60 秒）内没转完，就先返回视觉结果，台词在后台继续；同一视频再调用一次即可看到缓存好的台词。

## 官方语音输入插件显示未就绪

**现象**：状态卡显示「官方语音输入 · 未就绪」，或 `engine=host` 时返回 `host_not_ready` / `host_missing_service`。

**确认**：

1. 官方语音输入插件已在插件管理页启用。
2. 它的插件详情页已完成「下载并准备」，provider 处于 `ready` 或 `standby`。
3. 语言在 provider 支持范围内（`auto` / `zh` / `en` / `yue` / `ja` / `ko`）。`zh-CN`、`en-US` 等地区标签会归一化到基础语言；空白按自动识别处理。
4. 没有使用旧版 `audio.asr.provider`。旧 provider 非 `none` 且 `engine=auto` 时仍走 legacy，不会自动复用官方模型；请把 `engine` 设为 `host`，或清空旧 provider。

**边界**：

- 模型未准备时，本插件只提示，不自动下载。
- `engine=host` 不会回退云端或 whisper；需要回退时改用 `auto` 或 `local`。
- 官方 provider 没有段内时间戳，台词按块挂载；块长不超过 15 秒。
- 首次调用要唤醒官方 worker，可能比后续调用慢。


## 字幕有，但没挂到画面上

**确认**：`audio.status` 是否为 `ok`，`audio.segments` 是否为空。

- 外挂字幕：与视频**同名**的 `.srt` / `.vtt`（如 `demo.mp4` + `demo.zh.srt`；多语言段 `demo.zh.en.srt` 也识别），放在同目录；编码支持 UTF-8，GBK 与 Big5 自动回退。
- 内嵌字幕：软字幕才可提取；硬字幕属于画面内容，不是字幕轨。
- 字幕时间轴与视频对不上时，按 PTS 挂载会出现偏移，先确认字幕本身对齐。

## 下载失败

**现象**：进度条停住或报「下载失败，已尝试 N 个源」。

**常见原因**：网络到 Hugging Face / GitHub 不通、代理未生效、磁盘空间不足。

**修**：

1. 重试即可续传（已下载部分保留为 `.part`）。
2. 换源：设置环境变量后重启 DSH。

   ```text
   DSH_PF_STREAM_MODEL_BASE=https://hf-mirror.com
   DSH_PF_STREAM_WHISPER_URL=<whisper.cpp 压缩包完整 URL>
   ```

3. 磁盘：small 模型约 190 MB，引擎压缩包约 3.6 MB（解压后十几 MB），缓存目录默认 `~/.dsh/cache/dsh-pf-stream`。

文件完整性目前按大小校验（模型 > 1MB、下载字节与 `content-length` 一致），不是逐字节哈希。

### 一键安装不支持当前平台

一键安装只在 Windows x64 提供 whisper.cpp 压缩包。其他系统请先安装 whisper.cpp，然后在配置文件填写：

```yaml
audio:
  asr:
    local:
      binPath: /usr/local/bin/whisper-cli
      # modelPath: /path/to/ggml-small-q5_1.bin
```

已经用 PATH 装好 `whisper-cli` 时可以不填 `binPath`，插件会自动探测。也可以改用云端转写。

## 确定性检视只出了部分包

**现象**：`uniform`/`timestamps` 一次调用返回的包数少于请求的 `frame_count`，末尾多出一条"已达单次调用包数上限/预算"提示行。

**原因**：包数受 `maxPacketsPerCall`（默认 20，与宿主单条消息 20 图上限对齐）或 `max_tokens_budget` 钳制，超出部分的时间轴尾部不再采样——这是设计行为，提示行会如实告知。

**修**：缩小 `pts_window` 或分批调用覆盖其余时间段；确需更多包时在 intent 里显式传 `max_packets`（仍受 20 图上限钳制）。

## 整片窗口卡满 15 分钟后超时

**现象**：`pts_window` 给了全片跨度（或跨度 >> 240s），调用长时间不动，最后报 `tool call timed out`。

**原因**：预算门只在出包点生效，整段低出包内容（台词片长镜头）会让解码一路跑窗，撞上客户端 900s 上限。

**修**（新版已内置自愈）：

- 插件已加墙钟门：推进超过 `maxWallClockMsPerCall`（默认 720s）即以 `telemetry.stopReason=wall_clock` 收敛并附提示行，已消费部分按游标续接；
- 调用习惯上按 `pts_window` 分段推进（建议单窗跨度 ≤240s），配合游标续窗即可覆盖全片；
- 机器负载重时每窗耗时会拉长，属正常，墙钟门保证不会死等。

## 转写很慢或超时

**基准**：CPU、small 量化模型，约 5 秒转 7 秒语音（本机实测 5.3s / 7.2s 音频）。长视频按块转写，块数与时长成正比。

**修**：

- 长视频把 `audio.graceMs` 调大（默认 60000；更长的窗口可设 120000），让首次调用多等一会儿；
- 或把 `audio.asr.local.timeoutMs` 调大（默认 300000）；
- 机器弱就换云端，或换更小的模型（`base-q5_1`，约 60MB，准确率下降）。

## 中文识别不准

1. 确认配置里的 `audio.asr.language` 是 `zh`；单次调用也可用 `audio.language` 传语言提示（会话里说「用中文转写」也会传）。
2. 换更大的模型：`small` → `medium`（约 540MB，慢一倍以上）。
3. 背景音乐、多人抢话、远场录音本身就会掉准确率，这不是配置能修的。

## 设置页只读

**现象**：高级区显示「配置只读」，或保存时报错。

**原因**：插件条目被上层配置覆盖（宿主 patch、命令行覆盖、Home patch），写入会被拒绝。

**修**：改覆盖它的那份配置（通常是 profile 的 `cordis.patch.yml`），或删掉覆盖项后重启。面板底部会提示「配置由宿主管理」。

## 重启后视频从头看了

**现象**：DSH 重启后再看同一个视频，流式调用从片头重新开始（此前已消费的时间段重新出包）。

**原因**：会话状态落盘没生效——通常是宿主没提供 `storageDomain`（未配置存储后端）或插件配置 `persistSessionState` 被关了。落盘正常时，重启后同会话从最近一次成功调用的游标续接。

**修**：

1. 检查宿主日志有没有 `[dsh-pf-stream] storageDomain` 开头的告警：有「设施不可用」是宿主没提供该能力（升级 DSH 或配置存储后端后重启）；有「打开领域 'pf_stream_sessions' 失败」按告警里的原因处理（多为存储后端路由未配置），插件会在 30 秒后重试。
2. 确认插件配置 `persistSessionState` 没有被上层配置覆盖为 `false`；关闭时不会尝试打开领域，也不会打日志。
3. 落盘保留最近 8 个会话，更早的会话已淘汰，属正常。

## 升级后行为没变

宿主对已加载的模块做进程内缓存。**升级插件后必须重启 DSH 应用**，host 半的新代码才会生效；只刷新页面只更新面板。

## 面板打不开 / 接口 404

面板请求 `/dsh-pf-stream/api/status`。若返回 404：

1. 确认插件已启用（不是只安装）；
2. 重启 DSH；
3. 没有 Web 服务的宿主不提供设置面板，但工具本身仍可用；若日志出现 `[dsh-pf-stream] 可选服务 webServer 注入失败/接线失败`，按错误信息处理（通常是宿主 Web 服务未就绪或路由已被占用）。

## 想彻底重置

1. 关闭 DSH；
2. 删除 `~/.dsh/cache/dsh-pf-stream`（会删掉模型、引擎与转写缓存）；
3. 重启后重新在面板里下载。

密钥不在此目录：密钥存在宿主的凭据存储里，面板里「清除」即可。
