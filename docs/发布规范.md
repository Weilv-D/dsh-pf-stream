# 发布规范

## 版本策略

- 单一版本源：`package.json` 的 `version` 字段。tag、GitHub Release、npm 版本三者由它派生，不允许出现不一致。
- 语义化版本，0.x 阶段约定：
  - `minor`（0.1 → 0.2）：破坏性变更或新增能力（新画布形态、新 action、新配置项）；
  - `patch`（0.1.0 → 0.1.1）：缺陷修复与文档更新；
  - 宿主（DSH GUI）集成验证通过后升 `1.0.0`。

## 发布通道

npm 发布走 GitHub Actions Trusted Publishing（OIDC），不使用本地命令、不存储 npm token。

- 触发：GitHub Release 发布（`on: release: published`）。只有 Release 能触发发布，普通 push 不发包。
- 门禁：`build` → `test`（含 e2e，runner 自带 ffmpeg）→ `verify:host`，任一失败即中止。
- 守卫：Release 的 tag 必须等于 `v{package.json version}`，否则工作流直接失败。
- 产物：`npm publish --provenance`，npm 页面显示来源仓库与 commit。

## 一次性配置（已由仓库维护者在 npmjs.com 完成）

包 `dsh-pf-stream` → Settings → Trusted Publishers，绑定：

- Repository: `Weilv-D/dsh-pf-stream`
- Workflow: `publish.yml`
- Environment: 留空

绑定后，只有该仓库该 workflow 的运行能发布此包。

## 发布步骤

1. 确认 `main` 分支为待发布状态，CI 绿。
2. 升版本并打 tag（在仓库根目录）：

   ```powershell
   npm version patch   # 或 minor
   git push --follow-tags
   ```

3. GitHub 仓库页 → Releases → Draft a new release → 选择刚推送的 tag（`v0.1.0` 形态）→ 填写变更要点 → Publish release。
4. CI 自动跑门禁并发布。Actions 页面确认 `publish` 工作流绿。
5. 验证：`npm view dsh-pf-stream version` 输出新版本号。

## 回滚与修复

npm 发布不可撤销。线上问题用新 `patch` 版本修复再发，不在旧版本上做任何覆盖尝试。

## 附注

- 历史：`0.0.0-stage` 为 npm 侧暂存占位版本（包名持有用），非本仓库产物；`0.1.0` 发布后自动成为 `latest`。
- 本地直接 `pnpm publish` 仍可用于紧急情况，但常规发布一律走 CI。
