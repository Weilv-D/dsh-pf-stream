# 发布规范

## 版本策略

- 版本源唯一：`package.json` 的 `version` 字段。tag、GitHub Release、npm 版本三处一致。
- 版本号遵循语义化版本。0.x 阶段约定：
  - `minor`（0.1 → 0.2）：破坏性变更或新增能力（新画布形态、新 action、新配置项）。
  - `patch`（0.1.0 → 0.1.1）：缺陷修复与文档更新。
  - 宿主（DSH GUI）集成验证通过后升 `1.0.0`。

## 发布通道

发布通道为 GitHub Actions Trusted Publishing（OIDC）。发布凭据由 GitHub OIDC 身份即时签发；仓库与 npm 侧无长期凭据。

- 触发源限定 GitHub Release（`on: release: published`）。push 与 pull request 仅运行 CI。
- 门禁顺序：`build` → `test`（含 e2e，runner 自带 ffmpeg）→ `verify:host`。任一步失败即中止发布。
- 守卫：Release tag 必须等于 `v{version}`。tag 与 `package.json` 不一致时，工作流在守卫步失败并报错。
- 产物命令：`npm publish --provenance`。npm 页面显示来源仓库与 commit。

## 一次性配置

npmjs.com 包设置绑定 Trusted Publisher：

- Repository：`Weilv-D/dsh-pf-stream`
- Workflow：`publish.yml`
- Environment：留空

绑定后，发布权限仅授予该仓库该 workflow 的运行。

## 发布步骤

1. 确认 `main` 分支 CI 绿。
2. 在仓库根目录升版本并推送 tag：

   ```powershell
   npm version patch   # 或 minor
   git push --follow-tags
   ```

3. GitHub 仓库页 → Releases → Draft a new release → 选择刚推送的 tag（`v0.1.0` 形态）→ 填写变更要点 → Publish release。
4. 在 Actions 页面确认 `publish` 工作流绿。
5. 运行 `npm view dsh-pf-stream version`。输出为发布版本号即成功。

## 回滚

npm 版本一经发布即固定。线上问题的修复方式固定为发布新 `patch` 版本。
